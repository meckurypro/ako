8. ICON DESIGN CONSTRAINTS

The final Akọ interface icon assets should be designed around these principles.

Format

Prefer:

SVG

where appropriate.

SVG should be the default for interface icons because these icons need to remain crisp across screen densities and sizes.

If a particular icon genuinely requires raster artwork, explicitly identify why.

Background

Icons must have:

transparent background

Do not bake a background color into the icon unless the design itself requires a genuine shape/background element.

Color

Do not bake unnecessary UI colors into the artwork.

The icon should be capable of being affected by CSS where technically appropriate.

For monochrome icons, prefer an implementation that allows the application to control the rendered color.

For example, where appropriate:

fill="currentColor"

or an equivalent CSS-controlled approach.

This allows the same icon to adapt to:

light/dark surfaces

active/inactive states

hover states

disabled states

Akọ theme colors

accessibility adjustments


Do not destroy this flexibility by hardcoding arbitrary colors into every icon.

Size

Icons must be lightweight.

They will frequently be displayed at relatively small sizes.

Design them to remain recognizable at approximately:

16px
20px
24px
28px
32px

where applicable.

Do not create unnecessarily complicated paths.

Avoid:

excessive path complexity

unnecessary metadata

embedded raster images

huge SVG files

unnecessary filters

unnecessary masks

unnecessary gradients

unnecessary animation


The objective is:

> Small file. Fast load. Clear silhouette. Strong identity.

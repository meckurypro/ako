# Sound & micro-interactions — status and what's left

Working log for the sound manager + micro-animation pass. Read this before
assuming a gap is an oversight — most of what's missing below is missing on
purpose, for a stated reason. If you're picking this back up, start here.

## What's built

**Sound manager** — `src/lib/sounds.ts` (event registry), `src/hooks/useSound.tsx`
(settings + playback), `src/lib/audioBus.ts` (shared Web Audio graph + ducking).
Settings UI lives in `src/pages/Settings.tsx` ("Sound" section) — on/off toggle,
Normal/Minimalist mode. 11 placeholder tones in `public/sounds/`, generated by
`scripts/generate_placeholder_sounds.py` — swap the files, not the code, when
real sound design is ready.

**Wired sound events**: `like`, `follow`, `message-sent`, `message-received`
(open thread only), `gift-sent`, `unlock-success` (purchase + gig booking),
`room-join`, `room-leave`, `error` (LiveKit connection failures only). See
each hook: `useReactions.ts`, `useProfile.ts`, `useMessaging.ts`,
`useGifting.ts`, `useProjects.ts`, `useLiveKitRoom.ts`.

**Micro-animations**: `LikeHeart.tsx` (pop + spark burst, shared by PostCard/
ProjectCard/CommentThread), `FollowButton.tsx` (pill "arrival" animation),
`GiftPicker.tsx` (gift pop + rising glyph on send), `UnlockReveal.tsx`
(blur→sharp reveal on purchase, wired into ProjectCard). Keyframes all live in
`src/index.css`, prefixed `ako-*`, with `prefers-reduced-motion` support.

**Haptics**: deliberately NOT implemented on web — see `HAPTICS.md` for why
(full React Native rewrite planned, so web haptics code would be thrown away)
and for the event→haptic mapping to implement directly in the RN build.

## What's left, and why it's not done yet

- **`gift-received` has no sound or animation.** This event needs to fire for
  the *recipient*, who isn't the one calling the mutation — that requires a
  realtime subscription to notifications, which doesn't exist anywhere in the
  app yet. Bolting one on just for a sound felt like solving the wrong
  problem first; this needs its own pass (a `notifications` realtime channel,
  probably feeding a live badge/toast too, not just this one sound).

- **No generic `error` sound beyond the one LiveKit spot.** There's no
  centralized toast/error system in the codebase — errors are ad hoc
  per-component state (`setError(...)` + inline text). `error` only fires
  today from `useLiveKitRoom.ts`, which had one clear, single error path.
  Wiring it more broadly means either building a toast system first or
  touching every error call site individually — hasn't been decided which.

- **No message bubble entrance animation.** `message-sent`/`message-received`
  sounds play, but the bubbles themselves still just appear. A quick
  slide/fade-in on new bubbles (own vs. other's, probably different) would
  pair naturally with the existing sounds.

- **No room join/leave visual.** Same gap as above but for `MeetingRoom.tsx`
  — `room-join`/`room-leave` sounds exist, no matching visual moment.

- **Ducking is untested on real devices.** `audioBus.ts`'s duck-under-media
  behavior (see there for how) has only been verified to build/type-check,
  not been heard on an actual phone yet — worth confirming the ducking ramp
  actually feels right once this is running on a device, not just in a
  browser tab.

- **Minimalist mode's event subset is a guess, not user-tested.**
  `MINIMALIST_EVENTS` in `sounds.ts` currently plays only
  `message-received`, `notification-generic`, `gift-received`,
  `unlock-success`, `error` — worth revisiting once someone's actually lived
  with it for a while.

- **`audioBus.ts` is very likely dead code after the React Native rewrite.**
  Web Audio API has no RN equivalent; `expo-av`/`expo-audio` handles volume
  differently, and OS-level ducking under other audio is often automatic on
  mobile anyway. The *decision* to duck (and the event taxonomy) carries
  forward; this specific implementation almost certainly doesn't. Don't
  invest further in this file's sophistication with that in mind.

- **Placeholder sounds are still placeholders.** Obviously — but flagging it
  here so nobody mistakes the synthesized tones in `public/sounds/` for
  final sound design if this file is read out of context.
